## Causas y correcciones

### Los seis fallos y un error de Unit Tests en cd56bcd

Los fixtures omitían moonraker_host. En POSIX, localhost selecciona el transporte local y consulta el config_file activo antes de adquirir el lock. Los mocks cubrían el transporte remoto: la consulta HTTP real fallaba y producía FAILED_PRECONDITION antes de alcanzar la condición que cada test quería comprobar. Windows no tomaba esa ruta y ocultaba la dependencia.

| Test | Efecto del fallo original |
| --- | --- |
| test_backup_read_failure_prevents_firmware_action | Se abortaba antes de simular el fallo de backup. |
| test_concurrent_review_edit_aborts_before_snapshot_power_or_firmware | No se alcanzaba la detección de la edición concurrente. |
| test_legacy_version_string_cannot_replace_typed_build_identity | No se alcanzaba el rechazo de identidad tipada; se esperaba FAILED_FLASH. |
| test_prepare_only_strategy_cannot_enter_integrated_physical_workflow | El detalle del error correspondía a Moonraker, no al rechazo de prepare-only. |
| test_tampered_staged_artifact_cannot_enter_flash_workflow | No se alcanzaba el rechazo del hash alterado; se esperaba FAILED_FLASH. |
| test_firmware_workflow_receives_final_config_revalidation | Deployer no llegaba a construirse y call_args era None. |
| test_firmware_installation_reuses_the_configured_controller | La operación abortaba antes de ejecutar la secuencia simulada de alimentación. |

Corrección: host remoto explícito fixture-printer.invalid; aserciones de seguridad conservadas. Nuevas regresiones verifican la selección remota sin HTTP y que loopback POSIX sigue rechazando un config_file desconocido.

### Cuatro fallos pytest que la CI anterior no alcanzaba

- **test_pending_retry_activates_matching_files_and_honors_cancel:** el código omitía activation_selector cuando los archivos coincidían, aunque aún no se hubiese verificado su activación. Así ignoraba la elección de no reiniciar. Ahora solo omite la decisión en el reintento de verificación explícita. El test modela la configuración realmente cargada: rechaza la antigua, permite la activación explícita y comprueba que un reintento ya verificado no vuelve a reiniciar.
- **test_atomic_creation_preserves_edit_after_final_read:** esperaba el archivo de hardware separado en una instalación nueva. El contrato root-v1 publica directamente en printer.cfg. Ahora comprueba que la edición concurrente de ese archivo se conserva y que no aparece el archivo separado.
- **test_rollback_preserves_post_read_external_edit_on_real_files[True/False]:** ambos casos buscaban un artefacto separado aunque el plan era root-v1. Los fixtures ahora representan explícitamente ambos diseños: printer.cfg y el include administrado. Se ejecutan cuatro combinaciones, preservando las ediciones externas y el snapshot para recuperación manual.

### Distribución inmutable

Tras publicar el cambio de runtime, GitHub detectó que bootstrap y los comandos públicos seguían fijados al candidato anterior. La comprobación local había comparado candidate..HEAD, sin incluir los cambios pendientes. Se fijaron los instaladores al runtime real 8d46568 y se reforzó el test para comparar también el índice y el árbol de trabajo. Se comprobó deliberadamente en una copia aislada que ahora rechaza un cambio de runtime no fijado.

Studio usa ese runtime, el bootstrap de e19883b y hashes calculados de bytes reales. Se verificaron por descarga el instalador, todos los archivos exigidos del runtime y el bootstrap. Las copias de bootstrap de ambos proyectos son idénticas: SHA-256 e16f24ca00a8b346b5996e35edee3d9e1e46c7629c6aac29616668bedd8d06d2.

### Otros hallazgos

- Los tres tests de mensajes de exportación suponían estar fuera de Docker. Los fixtures ahora seleccionan explícitamente host/contenedor y tienen una regresión adicional para las rutas montadas; se conservaron las aserciones originales.
- El fallo histórico STM32 de f997a97 ya estaba corregido por 6e12d9f en main: reloj explícito de 8 MHz para STM32F103 y 12 MHz para STM32F446. No se introdujeron relojes implícitos. Se verificaron las cinco compilaciones reales del job de CI.

## Cierre de portabilidad y protección de main

Se revisaron los 292 archivos versionados de KACE y los 110 de Studio antes
de añadir este informe, incluyendo una búsqueda de identificadores personales
en los bytes de los archivos. Se sustituyó la carpeta personal de los fixtures
por entradas sintéticas y la ruta Windows fija de la vista previa de Studio
por un nombre de archivo relativo. Se conservaron rutas de servicio de la Pi,
ejemplos genéricos y fixtures necesarios de unidades extraíbles.

Los detectores ahora cubren perfiles con separadores escapados o puntos,
directorios personales y rutas absolutas de la unidad secundaria sin depender
del nombre de la carpeta del desarrollador. Ya no excluyen archivos de tests
ni directorios versionados de build/dist. El hook de KACE reutiliza el detector;
una regresión verifica su funcionamiento cuando se copia a `.git/hooks`.

`main` tiene PR obligatorio, checks estrictos con la rama actualizada, cero
aprobaciones manuales, protección aplicada a administradores, y force-push y
eliminación deshabilitados. KACE exige ocho checks, incluido el barrido completo
que ahora también corre en PR; Studio exige siete, incluidas las cuatro
combinaciones de tests y ambas compilaciones Windows. Las publicaciones
firmadas y la matriz full conservan sus disparadores existentes.
